# Portable decision aids

A decision aid helps a leader make one choice before they have any reason to buy. The recipient should be able to forward it without explaining Mindmake or exposing the person who prompted it.

## Select a real decision

Examples include: which pricing assumption to test with buyers; which leader judgement to capture before delegating a task; what evidence would change a build-or-partner choice; which team decision needs clearer authority. Choose one. Do not produce a generic AI readiness score or an unsolicited diagnosis.

## One-page content contract

1. **Decision:** the choice in one plain sentence, with the intended reader role.
2. **What changed:** two or three supported observations, with compact source references and dates.
3. **Options:** a fair account of the plausible routes, including keeping the current approach when reasonable.
4. **Trade-off:** the condition under which each option makes sense and the evidence that would change the choice.
5. **Small test:** one reversible action, the signal to watch and the limit that prevents false certainty.
6. **Boundary:** outside-in work is an illustrative view, not advice, to test against the real business. State what the sources cannot tell us.

The aid may have no ask. If an ask serves the reader, use one approved route and at most one link beyond source citations. Do not turn source citations into tracked sales links. Avoid public delivery-duration promises, pricing, availability and private product invitations.

## Two versions when needed

The private named version may use only authorised recipient context. Its permitted audience travels with the artifact. The reusable practice version removes personal details, confidential context and identifying combinations. Removing a name alone does not anonymise a case. Keep private evidence in Control Center and link its authorised reference rather than copying it into Git.

Research supports external commentary. It does not become "what we saw with a client". Client proof needs the right proof family, exact approved quotation if used, and permission for this placement. Current public proof permission does not automatically clear an attachment sent in a new context.

## Review and handoff

Read the aid as the recipient: can they state the choice, see the alternative and run the test? Check source support, uncertainty, anonymisation, one ask and a working destination. The Markdown artifact is ready for content review; a PDF or designed version needs separate rendering and visual checks before use. No playbook text claims a rendered file exists.
